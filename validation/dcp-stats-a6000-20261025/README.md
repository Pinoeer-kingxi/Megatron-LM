## Performance protocol

The existing interval timer measures fixed CP2, DCP metrics off and DCP metrics on. Each arm resumes the same checkpoint, performs 100 updates, drops ten warmups and retains 90 steady updates. Three repetitions rotate arm order. Every step processes 2,560 effective tokens. Stdout and TensorBoard are enabled at log interval one; W&B is disabled. Primary timing runs exclude tensor hashing and CPU profiling.

All timing arms use GPUs 2 and 4, with the same CPU affinity in every run: rank 0 `[0,2,32,34]`, rank 1 `[4,15,36,47]`. `host.json` records topology and shared-host conditions; `bound-gpu.csv` records GPU activity, clocks, temperature and power throughout the measurement. The host has unrelated workloads. These measurements do not establish zero observation overhead or production-model performance.

| Arm | Mean step ± between-run sample std (ms) | Median of run medians (ms) | Mean effective tokens/s |
|---|---:|---:|---:|
| Fixed CP2 | 142.71 ± 5.09 | 139.95 | 17,954 |
| DCP, metrics off | 111.98 ± 4.50 | 108.10 | 22,886 |
| DCP, metrics on | 110.88 ± 5.46 | 107.75 | 23,125 |

The metrics on/off mean difference is **-0.98%**, with paired differences **-9.72% to +5.38%**. The paired sample does not resolve a small observation cost; the negative mean difference is not evidence that enabling metrics accelerates training. Fixed CP2 / DCP-off mean step ratio is 1.274 for this specific workload.

A separate 40-update-per-arm CPU diagnostic, with ten warmups excluded, measured schedule statistics at 39.8–40.1 µs/step and window updates at 12.3–12.4 µs/step. The emitting rank's whole existing `training_log` call averaged 1.483 ms off and 1.447 ms on. The logging mean difference is also subject to shared-host variation. These samples time existing Python function boundaries, without per-operator GPU timers, and are excluded from primary performance aggregates. `cpu-profile-summary.json` is reproduced by `analyze_cpu_profile.py` from the retained diagnostic rows.
