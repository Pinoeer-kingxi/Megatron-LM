#7908 逐项核查

gdn.py（两个实际新增代码块）：
  offload_core_attention 沿用 attention.py 的配置派生习惯；不另外添加 manager 或异步流。
  选择真实可微输入是为了让 group-start backward hook 实际执行。冻结 projection 后可仅剩可训练 gate，固定用 Q 会漏掉预取；全冻结、eval 和 no-grad 旁路不初始化 manager。这些不是无依据的兜底。
  scope 只包围 FLA recurrence；commit 位于原始输出、norm checkpoint 之前。这个位置使 H2D 等待先于 FLA backward。输入可能与 scope 外保存张量共享 storage，不使用 forced release 是必要的生命周期边界。

#8243 核查

  forward_only 明确来自三个 native schedule；共享 manager 不额外猜测训练阶段。forward-only evaluation 创建空 chunks 不应消费训练 warmup。
  fraction=0 覆盖 warmup 时无合格 tensor、之后尺寸增长的 group，否则后续会实际复制。
  finish_all_groups 按剩余同名 forward group 判断，避免把“没有待传输数据”当成“forward 已完成”。
  fallback reload 等待 D2H event，避免读取尚未写完的 host backup。
  pool buffer 在 H2D 入队后即归还，下一次 D2H 写入前必须建立顺序。所有 chunk 共用 manager 的 H2D/D2H streams 和 pool，当前 wait_stream 能覆盖跨 chunk 复用。没有发现需要另建 per-buffer event 框架的证据。
  相关测试用已有 core_attn scope 复现，修复没有依赖 GDN。
